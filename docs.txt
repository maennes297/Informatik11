### **Das Sender Empfänger Modell**
Kommunikation lässt sich im Allgemeinen mit dem Sender-Empfänger-Modell beschreiben
; Ein Sender möchte eine bestimmte Nachricht übermitteln (Diese Nachricht enthält Informationen)
; Dafür *codiert* er sie in ein oder mehrere Signale.
; Die Signale werden übertragen (z.B. visuell, elektrisch... )
; Der Empfänger erhält die Signale und *decodiert*, um die darin enthaltenen Informationen zu erhalten.
Bei der Übertragung einer Nachricht können an verschiedenen Stellen Probleme auftreten:
- Bei der Codierung/Decodierung können Fehler auftreten (z.B. wenn die Decodierungsmethode unbekannt oder ungenau ist)
- Es können Signalstörungen auftreten
- Sicherheitsaspekte: Unbeteiligte können den Kommunikationsprozess abhören
- Die Übertragungsgeschwindigkeit kann zu Problemen führen
- Es können Kollisionen von Nachrichten auftreten, wenn die Leitungen nicht für die Anzahl an Nachrichten ausgelegt ist

### Domain-Name-System (DNS)
<p>
Das DNS ist ein System, welches Namen zu Ip-Adressen übersetzt. Für den Menschen ist es deutlich einfacher,
sich einen Text zu merken, als eine Zahlenkette. Darum gibt es Domain-Namen. Diese finden sich in der URL immer nach dem '://' und
vor dem nächsten '/'.
DNS ist ein dezentrales Netzwerk. Das bedeutet, dass die Server für das System über die ganze Welt verteilt stehen.
Um eine Ordung zu gewährleisten sind die Server untereinander Hierarchisch strukturiert. Dafür gibt es verschiedene Ebenen.
</p>
<p>
Diese Ebenen werden im Domain-Namen sichtbar. Ein Domain-Name wird immer von rechts gelesen.
Eine Ebene (auch Label genannt) wird immer mit einem Punkt abgeschlossen. Ein Label kann 1 - 63 Byte groß sein,
wobei der Domain-Name nicht größer als 255 Byte groß sein darf. Die Labels werden Anhand ihrer Position benannt. 
Nimmt man zum Beispiel den Domain-Namen 'www.example.com' ist 'com.' die Top-Level-Domain, 'example.' die Second-Level-Domain usw.
und 'www.' ist schließlich die Sub-Level-Domain und gibt den Nutzen an: 'www.' für Internetseiten, 'ftp.' für Dateiübertragung etc.
</p>
<p>
Der Nutzer kann nun eine Anfrage Senden. Diese enthält unter anderem den Domain-Namen.
Für die Anfragen gibt es zwei Verschiedene Arten: rekursiv und iterativ.

**Rekursiv**: Bei der rekursiven Auflösung sendet der Client (also das Gerät des Nutzers) erstmal eine Anfrage an seinen eigenen
lokalen DNS-Cache. In diesem werden kürzlich besuchte Internetseiten gespeichert. Ist die Seite im lokalen DNS-Cache schon bekannt, 
gibt dieser die IP-Adresse direkt zurück. Ist die IP-Adresse nicht bekannt, fragt der DNS-Resolver (das eigentliche
Übersetzungsgerät) eine Ebene höher nach, ob die IP-Adresse bekannt ist. Im Falle eines WLANs wäre das zum Beispiel der WLAN-Router.
**Iterativ**: Bei der iterativen Auflösung sendet der DNS-Resolver auch eine Anfrage an den Root-Nameserver. Dieser sendet dann aber nur eine weitere Anlaufstelle an den DNS-Resolver, bei der dieser dann auch nachfragt. So geht das dann weiter und der DNS-Resolver fragt solange weiter, bis einer der Server die IP-Adresse kennt. 
</p>
